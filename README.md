# IDEA MECE — AI 기반 기업 비즈니스 아이디어 도출 솔루션

주제를 입력하면 **서로 겹치지 않고 빠짐없이(중복·누락 없이)** 구성된 하위 아이디어를
무한 단계로 확장하고, 최종적으로 실무에서 바로 활용 가능한 **서술형 워드 보고서**를
만들어 주는 Flask 웹 애플리케이션입니다.

배포된 URL에 브라우저로 접속해 사용하므로, **안드로이드 스마트폰에서도 그대로 사용**할 수 있습니다.

이 저장소에는 **두 가지 버전**이 들어 있습니다.

| 버전 | 위치 | 서버 | 비용 | 배포 방법 |
|---|---|---|---|---|
| **정적 버전 (권장)** | `docs/index.html` | **불필요** | **0원** | GitHub Pages · 파일 전달 · 홈 화면 설치 |
| Flask 버전 | 저장소 루트 | 필요 | 무료~유료 | Render · Railway 등 |

**정적 버전이 기본입니다.** HTML 파일 하나에 모든 기능이 들어 있어 서버·설치·회원가입이
필요 없습니다. Flask 버전은 기존 방식이 필요할 때를 위해 함께 보관되어 있습니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 무한 확장 아이디어 | 주제 → 하위 아이디어 → 그 하위 아이디어 … 깊이 제한 없이 확장 |
| 항목별 개별 생성 | 각 항목마다 생성 개수를 지정해 원하는 가지만 더 깊게 전개 |
| 수정 / 삭제 | 항목 내용 직접 수정, 삭제 시 하위 항목 전체 자동 삭제 |
| 보고서 생성 | 제목 나열이 아닌, 각 내용을 해석·재구성한 서술형 보고서 집필 |
| 워드 다운로드 | 표지·쪽번호·제목 서식이 적용된 .docx 파일 (마크다운 기호 완전 제거) |
| 메일 작성 | 기본 메일 프로그램(Outlook 등)을 열어 제목·본문 자동 입력 |
| 소스 zip 받기 | Flask 폴더 구조 그대로 전체 소스를 zip 한 개로 다운로드 |

## 화면 사용 순서

1. 우측 상단 **[설정]** → Gemini API 키 입력, 모델 선택, 이메일 등록 후 저장
2. **검토 주제**와 **생성 개수**를 입력하고 [아이디어 생성]
3. 각 항목의 숫자 입력란에 개수를 넣고 [아이디어 생성]을 눌러 원하는 만큼 깊게 확장
4. 필요 없는 항목은 [삭제], 내용이 아쉬우면 [수정]으로 직접 보완
5. **[보고서 생성]** → 요약 확인 → **[워드 파일 다운로드]**
6. **[메일 작성]** → 메일 창이 열리면 내려받은 워드 파일을 직접 첨부하고 발송

> **첨부 관련 안내**
> 브라우저 보안 정책상 메일 창에 파일을 자동으로 첨부할 수 없습니다.
> 워드 파일은 별도로 다운로드되며, 사용자가 메일 창에 직접 첨부한 뒤 직접 발송해야 합니다.
> 시스템이 임의로 메일을 발송하는 일은 없습니다.

## Gemini API 키 발급

1. <https://aistudio.google.com/app/apikey> 접속 후 구글 계정 로그인
2. **Create API key** 로 키 생성 후 복사
3. 이 앱의 **[설정]** 모달에 붙여넣고 저장

키는 **서버에 저장되지 않습니다.** 사용자의 브라우저 세션에만 연결되어 서버 메모리에
격리 보관되며, 일정 시간(기본 2시간) 후 자동 폐기됩니다. 여러 사람이 같은 배포 URL에
동시에 접속해도 서로의 키가 섞이지 않습니다.

### 선택 가능한 모델

| 모델 | 특징 |
|---|---|
| `gemini-3.6-flash` | 최신 모델. 품질이 가장 좋아 기본값으로 권장 |
| `gemini-3.5-flash-lite` | 응답이 빠르고 사용량 한도에 여유 |
| `gemini-3.1-flash-lite` | 가장 가벼움. 항목 수가 많을 때 유리 |

모델 목록은 `config.py`의 `ALLOWED_MODELS`에서 관리합니다. 더 최신 무료 모델이 나오면
이 목록에 한 줄만 추가하면 화면 드롭다운과 서버 검증에 동시에 반영됩니다.

## 정적 버전 배포 (서버 없음 · 무료)

`docs/index.html` 파일 하나가 앱 전체입니다. 아래 세 가지 방법 중 편한 것을 고르면 됩니다.

### 방법 1 — GitHub Pages 로 주소 공유 (권장)

팀원에게 주소만 보내면 되고, 기능을 고쳐도 팀원은 새로고침만 하면 됩니다.

1. 깃허브 저장소 → **Settings** → 좌측 **Pages**
2. **Source** 를 `Deploy from a branch` 로 두고, Branch 를 **`main`** / 폴더를 **`/docs`** 로 선택 → **Save**
3. 1~2분 뒤 `https://<계정>.github.io/IDEA_MECE/` 주소가 열립니다
4. 팀원에게 그 주소를 공유합니다

> 저장소가 비공개(Private)면 Pages 공개 기능은 유료 플랜에서만 됩니다.
> 무료로 쓰려면 저장소를 공개(Public)로 바꾸거나, 아래 방법 2를 쓰세요.
> 저장소를 공개해도 **API 키는 코드에 들어 있지 않으므로** 노출되지 않습니다.

### 방법 2 — 파일 하나로 전달 (APK 건네주듯)

1. 앱 화면 우측 상단 **[앱 파일 저장]** 을 누르거나, 저장소의 `docs/index.html` 을 내려받습니다
2. 그 파일을 메일·메신저·USB 로 전달합니다
3. 받은 사람은 파일을 **더블클릭**하면 바로 실행됩니다 (설치 불필요)

> 이 방식은 APK 와 같은 단점이 있습니다. 기능을 고치면 파일을 **다시 뿌려야** 하고,
> 누가 옛 버전을 쓰는지 알 수 없습니다. 그래서 방법 1을 권합니다.

### 방법 3 — 스마트폰 홈 화면에 앱처럼 설치

1. 방법 1의 주소를 안드로이드 크롬으로 엽니다
2. 우측 상단 메뉴 → **홈 화면에 추가**
3. 아이콘이 생기고, 눌러서 열면 주소창 없이 전체화면으로 뜹니다

## 정적 버전 사용 시 알아둘 점

- **각자 본인 Gemini API 키를 입력**합니다. 키는 그 사람의 브라우저에만 저장되며,
  구글 외의 어떤 서버로도 전송되지 않습니다(중간 서버 자체가 없습니다).
- 아이디어 내용은 **각자의 브라우저에 자동 저장**되어 새로고침해도 유지됩니다.
  다만 브라우저 데이터를 지우면 함께 사라지고, 팀원 간에 내용이 공유되지는 않습니다.
  중요한 결과물은 **워드 파일로 내려받아 보관**하세요.
- 설정의 **"이 기기에 키 저장"** 을 끄면 탭을 닫을 때 키가 지워집니다.
  공용 PC 에서는 꺼 두시길 권합니다.

## Flask 버전 배포 (서버가 필요한 기존 방식)

정적 버전으로 충분하다면 이 절을 건너뛰어도 됩니다.
서버에서 데이터를 한곳에 모아 관리해야 하는 경우에만 사용하세요.

### 1단계 — 깃허브 프라이빗 리포지토리 생성

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<계정>/<리포지토리>.git
git push -u origin main
```

`.env`는 `.gitignore`에 포함되어 있어 절대 커밋되지 않습니다. 키를 코드에 직접 적지 마세요.

### 2단계 — 호스팅 서비스 연결

#### Render — 청사진으로 한 번에 (가장 간단)

리포지토리에 포함된 `render.yaml` 덕분에 설정을 직접 입력할 필요가 없습니다.

1. <https://render.com> 로그인 → **New +** → **Blueprint**
2. 이 리포지토리 선택 → **Apply**
3. 빌드·실행 명령과 환경변수(`SECRET_KEY` 자동 생성 포함)가 자동 적용됩니다
4. 발급된 URL을 스마트폰 브라우저로 접속

> `render.yaml`은 `main` 브랜치를 배포하도록 지정되어 있습니다.
> 다른 브랜치를 쓰려면 파일의 `branch:` 값을 바꾸거나 Render 화면에서 변경하세요.

#### Render — 수동 설정 (청사진을 쓰지 않을 때)

1. <https://render.com> 로그인 → **New +** → **Web Service**
2. 깃허브 리포지토리 연결 (프라이빗 리포지토리도 연결 가능)
3. 설정값 입력
   - **Environment**: `Python 3`
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `gunicorn --workers 1 --threads 8 --timeout 300 wsgi:app`
4. **Environment** 탭에서 환경변수 등록
   - `SECRET_KEY` : 아래 명령으로 만든 랜덤 문자열
     ```bash
     python -c "import secrets; print(secrets.token_urlsafe(48))"
     ```
   - `FLASK_ENV` : `production`
   - `SESSION_COOKIE_SECURE` : `1`
5. **Create Web Service** → 배포 완료 후 발급된 URL을 스마트폰 브라우저로 접속

#### Railway

1. <https://railway.app> → **New Project** → **Deploy from GitHub repo**
2. **Variables** 탭에서 위와 동일한 환경변수 등록
3. Start Command는 `Procfile`이 자동 인식됩니다

#### PythonAnywhere

1. **Web** 탭 → **Add a new web app** → **Manual configuration (Flask, Python 3.11)**
2. 콘솔에서 리포지토리를 clone 하고 `pip install -r requirements.txt`
3. WSGI 설정 파일에서 `from wsgi import app as application` 지정
4. 환경변수는 WSGI 파일 상단에서 `os.environ.setdefault(...)`로 설정

> **무료 플랜 운영 특성**
> Render 무료 플랜은 일정 시간 접속이 없으면 서버가 잠들고, 다시 깨어날 때
> 프로세스가 새로 시작됩니다. 이때 **입력했던 API 키와 작업 중이던 아이디어 내용이
> 초기화**됩니다(키는 설정에서 다시 입력하면 됩니다). 작업 내용을 계속 유지해야 한다면
> 유료 플랜의 디스크(Persistent Disk)를 붙이고 `DATABASE_PATH`를 그 경로로 지정하세요.
> 중요한 결과물은 **워드 파일로 먼저 내려받아 두시길** 권장합니다.

> **워커 수 안내**
> API 키를 프로세스 메모리에 격리 보관하는 설계이므로 **워커는 1개(`--workers 1`)**,
> 동시 처리는 스레드(`--threads 8`)로 확보합니다. 워커를 늘리려면
> `services/security.py`의 `KeyVault`를 Redis 등 공유 저장소로 교체하면 됩니다.

## 로컬 실행

```bash
git clone <리포지토리 주소>
cd idea_mece

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # Windows: copy .env.example .env
# .env 파일을 열어 SECRET_KEY 를 랜덤 문자열로 교체
# 로컬 http 환경에서는 SESSION_COOKIE_SECURE=0 으로 설정

python app.py
```

브라우저에서 <http://127.0.0.1:5000> 접속.
같은 와이파이의 스마트폰에서 시험하려면 `http://<PC의 내부 IP>:5000` 으로 접속합니다.

화면 우측 상단 **[소스 받기]** 를 누르면 지금 실행 중인 전체 소스를
Flask 폴더 구조 그대로 zip 한 개로 내려받을 수 있습니다.

## 설계 요점

### 정적 버전의 워드 파일 생성

브라우저에는 python-docx 가 없습니다. 외부 라이브러리를 싣는 대신 **.docx 파일을 직접 조립**합니다.
.docx 는 실제로는 XML 문서 여러 개를 담은 ZIP 파일이므로, WordprocessingML 을 직접 만들고
브라우저 내장 압축 기능(`CompressionStream`)으로 ZIP 으로 묶습니다.
덕분에 500KB 짜리 라이브러리 없이도 표지·쪽번호·한글 글꼴·굵게 서식을 그대로 구현하며,
생성되는 파일도 6KB 수준으로 가볍습니다.

### 무한 확장 트리
`parent_id`(인접 리스트)와 `path`(`/1/7/23/` 형태의 물질화 경로)를 함께 저장합니다.
경로 컬럼 덕분에 하위 전체 조회·삭제가 재귀 없이 **단일 인덱스 스캔**으로 끝나고,
조상 조회도 경로를 파싱해 **쿼리 한 번**으로 처리됩니다.
825개 항목 기준 전체 조회·직렬화 약 4ms, 46단계 깊이의 조상 조회 약 0.2ms로 동작합니다.

### 중복·누락 없는 아이디어 생성
- 한 번의 분해에 사용할 **분류 기준을 하나만** 정하도록 모델에 먼저 출력시켜 기준 혼재를 막습니다.
- 상위 맥락은 **계층적으로 압축**해 전달합니다(최상위 주제는 전문, 직계 부모는 설명 전문,
  가까운 조상 2개는 요약, 그보다 위는 제목만). 깊이가 깊어져도 프롬프트 길이가 거의
  늘지 않아 생성 속도와 비용이 일정하게 유지됩니다.
- 이미 만든 같은 수준 항목과 부모의 형제 항목을 **침범 금지 영역**으로 함께 전달하고,
  응답은 서버에서 표기 차이를 무시한 키로 한 번 더 중복 제거합니다.

### 보고서 품질과 후처리
- 제목 나열이 아니라, 각 영역의 세부 내용을 근거로 **해석·재구성한 서술형**으로 집필합니다.
- 개발 과정 용어(MECE, 트리, 항목 분해, 생성 과정 언급 등)와 마크다운 기호는
  **5겹 방어**로 제거됩니다: 프롬프트 지시 → 정규화 → 용어 필터 → 구조 파싱(기호를 서식으로 변환)
  → 잔여 문자 스크럽 및 최종 감사.
- 워드 파일 생성 후에도 문서의 모든 텍스트 조각을 다시 검사하므로,
  `*`, `#`, 백틱 등이 파일에 남을 수 없습니다.
- 용어 필터는 **자기 참조 표현만** 치환합니다. 보고서 주제가 AI 사업인 경우에도
  'AI', '인공지능' 같은 정상 용어는 그대로 보존됩니다.

### 보안
- **API 키 격리**: 서버 전역 저장 없음. 세션별 메모리 금고에만 보관, TTL 후 자동 폐기,
  응답·로그에 원문 미노출(마스킹만 제공), URL이 아닌 헤더로 전송.
- **CSRF**: 상태 변경 요청은 세션 토큰과 `X-CSRF-Token` 헤더를 상수시간 비교로 검증.
- **XSS**: 서버는 입력을 정화해 저장하고, 화면은 `textContent`로만 출력(innerHTML 미사용).
  외부 리소스를 쓰지 않으므로 `script-src 'self'` 수준의 엄격한 CSP를 적용합니다.
- **접근 제어**: 모든 항목 조회·수정·삭제는 세션이 소유한 프로젝트 범위에서만 동작합니다.
- **경로 조작 차단**: 다운로드는 세션에 보관된 토큰→내부 파일명 매핑으로만 이루어지며,
  사용자 입력이 파일 경로에 직접 쓰이지 않습니다.

### 성능과 메모리
- 화면은 **부분 렌더링**만 합니다. 생성·수정·삭제 시 해당 노드(또는 그 자식 목록)의
  DOM만 갱신하고, 자식 DOM은 펼칠 때 처음 만듭니다(지연 렌더링).
- 이벤트는 컨테이너 한 곳에서 위임 처리하므로 노드를 지워도 리스너가 남지 않습니다.
- 보고서 본문은 영역별로 **제한 병렬 집필**(기본 3개 동시)해 대기 시간을 줄입니다.
- DB 커넥션은 요청 단위로 열고 teardown에서 반드시 닫으며, 금고와 생성 파일은
  주기적으로 만료분을 정리합니다. 반복 요청 시 메모리 증가가 0에 수렴하는 것을 확인했습니다.
